# 自己完成下一题：比赛与学习路线

官方页面核对日期：**2026-09-17**。下面的题目事实来自所链接的官方页面；学习次序与练习方法是本项目给出的建议，不是比赛官方路线。这里只给入口和阶段目标，不放这些题的完整解法。

## 1. 最接近本项目：AtCoder Heuristic Contest

AHC 关注在有限运行时间内找到质量更好的解，而不是只判断一个确定答案是否正确。这类题适合练习构造解、局部搜索、退火、束搜索、重建和优化实现，并能用同一批实例量化改进。入口：[AHC 赛事列表](https://atcoder.jp/contests/)。

### 建议第一题：AHC006 — Food Delivery

[官方题目、输入生成器与可视化入口](https://atcoder.jp/contests/ahc006/tasks/ahc006_a)

从 1000 个配送订单中选择恰好 50 个，并设计从配送中心出发、最后返回的路线；每个订单都必须先取餐再送达，目标是缩短曼哈顿总路程。原题程序时限为 2 秒，并提供本地工具和网页可视化。

它和本项目同属配送优化，但决策对象不同：本项目从预先给定的 `(bundle, rider)` 行中挑选，这道题自己选择订单与取送顺序。不能把这里的 solver 原封不动搬过去。

建议先自己写一个绝对合法的路线，再研究为什么其中有绕路、哪些选择被当前表示限制。先保留自己的第一个版本和分数，再看任何题解。目标是能解释每一次改进，而不是一开始追求复杂方法。

### 另一个入口：AHC001 — AtCoder Ad

[官方题目与工具](https://atcoder.jp/contests/ahc001/tasks/ahc001_a)

在给定区域中放置互不重叠、轴对齐的广告矩形，兼顾指定位置和目标面积。评分与这些要求的满足程度有关。它的几何状态直观，适合观察局部调整带来的影响；原题时限为 5 秒。

若希望先把“状态、合法变换、评分、接受规则”的框架独立搭完整，这题也合适。这里是入门顺序建议，不表示它容易取得高排名。

### 核对到的下一场

[AHC072：ALGO ARTIS Programming Contest 2026 September](https://atcoder.jp/contests/ahc072)

官方页面列出的时间是 **2026-09-25 19:00 至 2026-10-05 19:00，日本时间 UTC+9**；北京时间对应 18:00 至 18:00。这是长期赛。报名条件、奖励资格和规则以该场官方页面为准，不能因为能参赛就推断一定有领奖资格。

先练一道已结束的题，更容易按自己的节奏把整个循环完成，再决定是否参加限时赛事。

## 2. 想看自己写的程序“对战”：CodinGame

### Ultimate Tic-Tac-Toe

[官方题目与对战入口](https://www.codingame.com/multiplayer/bot-programming/tic-tac-toe)

入门联赛从普通井字棋开始，后续进入大棋盘中包含小棋盘的 Ultimate Tic-Tac-Toe。官方列出的学习内容包括 Minimax、Alpha-beta、Negamax 和 Monte Carlo Tree Search。

这条线更直接地连接到博弈搜索。建议先自己实现状态、合法动作和终局判定，再写一个基线玩家；之后每次只加一项搜索能力，用固定对手、足够多局和交换先后手来检验变化。初期不需要训练神经网络。

### Mad Pod Racing

[官方题目](https://www.codingame.com/multiplayer/optimization/mad-pod-racing)

通过程序控制赛车，逐步处理轨迹、速度、惯性等因素。官方提供渐进教程和对战过程。若更喜欢看动作与轨迹的变化，而不是棋盘局面，这个入口也值得尝试。

## 3. 更完整的多智能体竞赛：Battlecode

[官方主页](https://battlecode.org/) · [官方时间表](https://battlecode.org/schedule.html)

为机器人团队编写自治策略，涉及资源管理、路径规划、协作和对抗。它比单个静态优化实例多了交互与策略层，适合作为后续项目。

截至上述核对日期，官网明确写着 **Battlecode 2026 已于 2026-01-31 结束**，不能当作正在报名的赛事。官网允许任何人参与，但部分正式赛事和奖金仅面向学生队伍；下一届日期与资格需要再查官方公告。本页不推测 2027 的具体开赛日期。

## 4. 与 AlphaGo/AlphaZero 到底哪里相似

相似的是一个抽象思路：**搜索空间太大，先用评价信息决定把有限计算花在哪里。** 这是一种结构类比，不表示本项目与 AlphaGo 是同一个算法。

| 维度 | 本项目 | AlphaGo / AlphaZero |
|---|---|---|
| 主要对象 | 一个已知候选集合的配送优化问题 | 随对手动作演化的棋局 |
| 主要评价信息 | 从约束与真实成本计算的价格、对偶下界 | 学习得到的策略先验与局面价值 |
| 搜索方式 | LNS + 局部 B&B + 精确匹配 | 神经网络引导的 MCTS |
| 是否训练网络 | 否 | 是 |
| 数值的含义 | 校验通过的下界可用于安全剪枝和质量界定 | 价值预测通常不是可证明的最优值上下界 |

[AlphaGo 原始研究的官方摘要](https://research.google/pubs/mastering-the-game-of-go-with-deep-neural-networks-and-tree-search/)说明其结合策略网络、价值网络与搜索，训练包含人类专家棋谱和自我对弈强化学习。[DeepMind 的 AlphaZero 说明](https://deepmind.google/blog/alphazero-shedding-new-light-on-chess-shogi-and-go/)介绍了从游戏规则和自我对弈出发训练网络，再用网络指导 MCTS 的路线。不要把原始 AlphaGo 与后来的 AlphaZero 混成“都没有用人类棋谱”。

本项目的价格更新是优化算法，不是强化学习；“某些数值在反复更新”本身并不意味着系统在进行自我对弈或训练策略网络。

想独立体验这条路线，可以先把小棋盘的普通搜索/MCTS 做完整，再讨论是否加入小网络与自我对弈。这样规则、搜索和学习三个因素能分开理解，不必从复刻大规模围棋系统开始。

## 5. 推荐的独立练习流程

**第一阶段：只完成合法性。** 自己实现输入、状态、目标函数和最朴素方案。写验证器，能明确区分“非法”“合法但差”“超时”。保留第一份能运行的提交。

**第二阶段：一次只验证一个想法。** 每次改动前写下预期，例如它想改善哪些实例，可能牺牲什么。固定一批种子做配对比较，记录每例结果，而不仅是平均分或最好分。

**第三阶段：先理解搜索受什么限制。** 检查当前表示能不能到达希望的解，邻域能否表达联合变化，评分有没有被重复计算，时间花在候选生成还是搜索节点上。没有证据前，不默认“加深搜索”或“加神经网络”会解决问题。

**第四阶段：保留一批未用于调参的实例。** 用它们检验改进是否泛化。最后再读高分题解，区分自己已经发现的结构、缺少的知识和纯工程速度差异。

与辅助工具协作时，可以明确约定：先只解释题意和给反例；卡住后给一层提示；你提交自己的实现后再检查。不要在自己尝试之前让工具直接完成整套 solver，这样最终分数提高了，也很难确认自己真正掌握了哪一部分。

## 6. 正在进行的比赛必须另看 AI 规则

规则不是所有 AHC 都相同。[短期 AHC 规则 20260818 版（2026-09-07 有更新）](https://info.atcoder.jp/entry/short-ahc-llm-rules-en)原则上禁止赛中使用生成式 AI，仅有特定例外；该规则明确不适用于长期赛或过去题目的练习。

[AHC072 页面](https://atcoder.jp/contests/ahc072)则明确适用另一份长期赛相关规定，并限制让 AI 代理执行程序后根据结果自动反复改进。正式参赛前应逐项核对当场规则，不应把本项目这种自动开发、测试、改进的工作方式直接照搬到赛中。

学习建议的起点是 **AHC006 旧题**。先独立做出一个合法基线，再让自己的每项改动都有能复查的实验记录。
